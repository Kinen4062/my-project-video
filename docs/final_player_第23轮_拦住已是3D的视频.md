## 二、先把那段红色报错看清楚：它跟"视频是 3D 的"没关系

用户把红字当成了"3D 视频转换失败"的症状。实际上报的是这个：

```
'MaxRetryError("HTTPSConnectionPool(host='hf-mirror.com', port=443) ... SSLEOFError ...")'
  thrown while requesting HEAD https://hf-mirror.com/depth-anything/Depth-Anything-V2-Small-hf/resolve/main/config.json
Retrying in 1s [Retry 1/5].
```

三个事实（都查过）：

1. **模型早就下好了，就在本地**：
   `~/.cache/huggingface/hub/models--depth-anything--Depth-Anything-V2-Small-hf/snapshots/<rev>/`
   里 `config.json` + `preprocessor_config.json` + `model.safetensors`（**99 MB**）齐全。
2. **那些请求不是"下载"，是"问一句有没有新版本"**。`from_pretrained(model_id)` 默认
   会对每个文件发一次 **HEAD**，而 `final_player.py` 第 7 行把 `HF_ENDPOINT` 指向了
   `hf-mirror.com`，那个镜像时不时 SSL 断流 → 重试 5 次 → 红字刷屏。
3. 所以 —— **只要模型还不在内存里，转 2D 视频照样会刷这段红字。**

**这一条是这轮最值钱的判断**：如果只按用户说的"拦住 3D",用户去转 2D 的时候会撞上
一模一样的红字，然后合理地质疑"你不是修了吗"。所以这轮是**两件事一起修**。

### 修法：先只用本地缓存

```python
for local_only in (True, False):
    processor = AutoImageProcessor.from_pretrained(model_id, local_files_only=local_only)
    model = AutoModelForDepthEstimation.from_pretrained(model_id, local_files_only=local_only)
```
缓存够用（正常情况）→ 一次网都不联，红字从根上没了，顺带还能离线用；缓存不全（第一次用）
→ 才退回到原来那条联网下载的路。

实测：只用本地加载 **3.2 秒**，24.8M 参数，推理输出形状 `(1, 392, 518)` 正常。

## 三、判据怎么定：先打表，再选阈值

### 判据是什么

本程序的产物是 `left = remap(frame, x+shift)` / `right = remap(frame, x-shift)` 拼起来的
（见 `process_video_to_3d`，`max_disparity = 20`）—— 也就是**两半是同一幅画的两个视点**。
所以判据就是：**把两半按最佳全局位移对齐之后，还差多少**。

### 实测打表（11 个样本）

| 类别 | 样本 | err_best | 残差中位数 | **梯度中位数** |
| --- | --- | --- | --- | --- |
| 真 3D | 真实产物 `测试合成3D.mp4`（2560x720） | 9.39 | 4.00 | **41.32** |
| 真 3D | 合成 SBS 视差 6px | 4.93 | 1.00 | **32.20** |
| 真 3D | 合成 SBS 视差 12px | 0.77 | 0.00 | **32.08** |
| 真 3D | 合成 TAB（上下分屏） | 3.91 | 1.00 | **19.40** |
| 真 2D | `city.mp4` | 65.73 | 54.00 | 18.82 |
| 真 2D | 屏幕录制 1280x720 | 36.77 | 32.00 | 23.59 |
| 真 2D | `bug1.mp4` | 29.78 | 12.00 | 12.99 |
| 真 2D | 合成：2D + 左右黑边 | 110.87 | 100.00 | 4.12 |
| 真 2D | 合成：2D + 上下黑边 | 32.47 | 13.00 | 5.74 |
| **该死** | 合成：近乎纯色 | **0.06** | 0.00 | **0.00** |
| **该死** | 合成：翻黑场（前 1/3 全黑） | **12.00** | 8.00 | **2.00** |

### ⚠️ 最后两行才是真正的坑

**纯色帧的左右两半"完全一样"，残差 0.06 —— 比真 3D 的 0.77 还小。**
只看残差的话，翻黑场、纯色片头、纯黑过场**必然被误判成"已经是 3D"**，
然后用户会被拦住一个本该正常转的 2D 视频 —— 这比"多转一次"难受得多。

把它俩分开的唯一凭据是**这一帧有没有细节可比**（梯度中位数）：

* 3D 样本：19.4 ~ 41.3
* 2D 样本里"有内容"的：12.99 ~ 23.59
* 纯色 / 黑场：**0.00 ~ 2.00**

所以：**梯度中位数 < 8.0 的帧直接跳过、不参与投票**；整段视频一帧都不够判 → 返回 None（不拦）。

### 六个常量与它们的来历

| 常量 | 值 | 为什么 |
| --- | --- | --- |
| `DETECT_HALF_SIZE` | 200 | 半幅缩到这个宽度/高度再比 —— 统一"位移"的尺度，也让整件事够快 |
| `DETECT_MAX_SHIFT` | 8 | 在半幅 200px 上搜 ±8px（≈ ±4%）。实测真实产物在最佳位移是 2~5px |
| `DETECT_DETAIL_MIN` | 8.0 | 3D 最低 19.4 / 黑场最高 2.0，取中间 —— 两边都留 2 倍以上余量 |
| `DETECT_ERR_MAX` | 15.0 | 3D 最高 9.39 / 2D 最低 29.78，取中间 —— 1.6 倍余量 |
| `DETECT_MED_MAX` | 8.0 | 3D 最高 4.0 / 2D 最低 12.0 —— 2 倍余量，且和上一条**同时**满足才算 |
| `DETECT_VOTE_SHARE` | 0.6 | 够判的帧里 60% 投同一票才下结论（单帧说了不算） |

实测 11 个样本 **11/11 全对**，单次检测耗时 **65~425 ms**（大文件慢在 seek 上）。

## 四、约束怎么落地

### 判据**不看文件名**

`XXX.3D.1080p.mkv` 这种名字的片子里，很多其实是普通 2D 源（"3D" 只是发布标签）。
靠名字判会大面积误伤，所以只看像素。

### 认不出来一律**放行**（fail open）

把一段真 2D 拦住（用户想转却转不了）比放过一段已经是 3D 的（白转几分钟）更难受。
所以只在"证据够硬"时才下结论。

### 默认按钮是【否】，但留了"仍然转换"的出口

```
┌─ 这个视频已经是 3D 的 ─────────────────────┐
│ 检测到它本身已经是 3D 视频（左右分屏）：      │
│ 测试合成3D.mp4                              │
│                                             │
│ 再转一次，程序会把每一半再拆成左右两份，得到  │
│ 四格画面，还要白花几分钟。你要找的多半是它    │
│ 前面那个原始的 2D 文件。                     │
│                                             │
│ 如果确定是程序看错了（这确实是 2D 视频），    │
│ 点【是】照样转。                             │
│                          [ 是(Y) ] [ 否(N) ] │
└─────────────────────────────────────────────┘
```

* **默认按钮 = 【否】**（图里蓝框在【否】上）—— 说明里一路回车仍然是安全的；
  想强行转必须专门去点【是】。
* **为什么留出口**：识别总有看错的余地，做成硬拦截之后用户就只能来找作者改代码了。
  用户原话说的是"无法再次转换"，如果想更硬，把 `_confirm_convert` 里的
  `askyesno` 换成一句 `showwarning` + `return False` 即可（我在提交信息里也提了）。
* **不问文件名、不问大小、不问有没有同目录的 2D 原件** —— 少问一句少一个 bug。

### 顺带说：为什么不干脆"检测到 3D 就自动帮你找 2D 原件"

想过，否决了：本程序不知道原件的名字（`测试合成3D.mp4` 和它的源文件之间**没有记录**
任何关系 —— 转换产物落在 `%TEMP%` 且每次转换都是新随机名）。猜一件不存在的事不如
把话说明白："你要找的多半是它前面那个原始文件。"

## 五、怎么测：**绝不真的跑转换**

真转换 = 加载 Depth-Anything + 逐帧推理，几分钟起步。所以这一节的 19 项全部绕开它。

### 素材生成器（`tests/_harness.py`）

* `make_3d_fixture(dst, src, px, axis)` —— 照着 `process_video_to_3d` 的排法**手工拼**：
  左眼 = 原帧按 `+px` 采样、右眼 = 按 `-px` 采样。`axis="sbs"` 左右拼、`"tab"` 上下拼。
  常量视差 = "整幅画在同一个深度平面"，是 3D 里最平凡的一种，够用了。
* `make_flat_fixture(dst, src)` —— 纯色 + 顶上一窄条噪声。**那条噪声是刻意留的**：
  它让"整帧均值"看起来还有内容，而真正能识破它的是**中位数** ——
  这个素材就是用来钉住"别拿均值当判据"的。

### 19 项分四块

| 块 | 项数 | 钉住什么 |
| --- | --- | --- |
| ① 检测器本身 | 5 | 2D→None、SBS→sbs、TAB→tab、**纯色→None**、文件不存在→None 且不抛 |
| ② 守门逻辑 | 5 | 3D+【否】→不转；3D+【是】→放行；**2D → 一个对话框都不弹** |
| ③ 接线 | 3 | `start_conversion` 确实过了这一关；被劝住后 `is_converting` 仍是 False、没有留线程 |
| ④ 模型加载 | 6 | 缓存够用只联本地；本地不全退回联网；两条都不成 → 抛且**不留半套状态** |

④ 用假类替换 `fp.AutoImageProcessor` / `fp.AutoModelForDepthEstimation`，记录每次
`local_files_only` 的取值 —— 断言的是**顺序**，因为"先本地后联网"正是修红字的关键。

### 真机

用**用户那个真实的** `<视频目录>\测试合成3D.mp4`（2560x720，763 帧）跑了一遍：
点【转换为3d】→ 弹出上面对话框 → `is_converting` 仍是 `False`（确实没开始转）。

## 六、关键坑

### 1. 纯色帧的两半"完全一样" —— 只看残差必然误判

这条是本轮的核心。翻黑场／纯色片头是**每部电影都有**的东西，而它们的残差
（0.06）比真 3D 还低。没有"细节闸门"，这个功能上线第一天就会开始误伤正常视频。

### 2. 两个方向的"够判帧数"必须**分开数**

第一版把 SBS 和 TAB 的可用帧数合在一个 `usable` 里，于是真 SBS 视频变成了
"6 票 sbs + 0 票 tab，usable=12，需要 8 票" —— **谁都过不了线**。
一段视频不可能同时是左右分屏和上下分屏，两边的分母必须各自算。

### 3. 半幅必须先缩到统一尺度

"位移"是像素单位。不统一尺度的话，1280px 宽半幅上的 ±8px 和 200px 宽半幅上的
±8px 完全是两码事，一套阈值不可能同时适用。

### 4. 判"有没有细节"不能用均值

合成纯色样本里那条 6 行高的噪声带，能把整帧均值抬到看上去"有内容"（std 20.9）。
中位数如实地说"这块画面整体是平的"。**判据要选语义直接的那个。**

### 5. 假类测试必须多验一条"失败后不留半套状态"

`_load_depth_model` 里两个对象是**先都拿到手再一起挂上去**的。分两步赋值的话，
model 失败时 `image_processor` 已经非空，而外面判的是 `if self.model is None` ——
下次进来重走一遍，中间那段半套状态还容易让人以为"模型已经好了"。测试直接断言
失败后两个都是 `None`。

### 6. 写文件的测试素材要放在"每次跑都全新"的目录里

本环境沙箱**覆盖不了已存在的文件**（`cv2.VideoWriter` 第二次跑就红，报错还看着不像
权限问题）。所以素材目录用 `run_<pid>_<随机6位>`，和上一轮同一套办法。

## 八、留给后来人

### 铁律

* **`detect_3d_layout` 里的"细节闸门"不能删。** 删了之后翻黑场和纯色片头会被判成
  3D（残差比真 3D 还小），而这个功能就开始误伤正常视频了。
* **判据不看文件名。** `XXX.3D.1080p` 里"3D"经常只是发布标签。
* **认不出来一律放行。** 拦错一段 2D 比放过一段 3D 更难受。
* **SBS / TAB 的可用帧数分开数**，别合成一个分母。
* `_load_depth_model` 里**先本地后联网**的顺序不能改回去 —— 改了红字重试日志就回来。
* **两个对象一起挂上去**，别分两步赋值。
